# 작업 운영 지침

## 실행 환경

- 이 작업은 별도 직원용 앱이 아니라 저장소 전체를 그대로 사용하는 하나의 Codex Desktop Local Project에서 수행한다.
- 준비 PC와 작업자 PC는 동일한 `app`, `scripts`, `templates`, `jobs` 구조와 동일한 규칙·기능을 사용한다.
- 작업자 PC에서는 이 저장소 루트를 Codex 데스크톱 앱의 Local Project로 열고, 현재 `jobs/<job-id>`의 상태를 이어서 작업한다.
- `검수화면_열기.cmd`는 같은 프로젝트의 HTML 검수 화면을 여는 편의 실행 파일이며, 저장소 내부 상대 경로만 사용한다.

## 정본

- `00_input/original.pptx`는 읽기 전용 원본이다.
- PPTX 발표 순서와 장수가 정본이다.
- PNG ZIP은 화면 비교 기준이며 압축 내 순서로 슬라이드 번호를 복구한다.

## 단계

1. `01_inventory` 인벤토리와 누락 이미지를 확인한다.
2. `02_triage/criteria.json`의 분류 기준을 적용해 모든 페이지를 `유지`, `재작업`, `판단 필요`로 분류한다.
3. `03_style`에서 프라이머리 컬러와 디자인 규칙을 확정한다.
4. 승인된 대표 시안 없이 전체 재작업을 시작하지 않는다.
5. `재작업`으로 확정된 페이지만 버전별로 생성한다.
6. 승인된 버전만 최종 PPT 복사본에 반영한다.

## 분류 기준과 재작업 계약

- 분류 기준과 제작 기준을 혼동하지 않는다. 장식이 적어도 핵심 내용이 읽히고 위계와 문맥이 분명하면 `유지`다.
- `재작업`은 원거리 가독성, 정보 과밀, 위계·흐름, 잘림·흐림, 문맥 전달 실패가 실제로 확인된 페이지다.
- 원본 참조가 없어 판독 가능성을 검증하지 못하면 `판단 필요`다.
- 재작업 시 원문, 숫자, 출처, 사진, 로고, 기존 일러스트와 의도된 강조를 보존한다.
- 16:9, 1920×1080을 유지하고 핵심 본문은 40pt 이상을 기본으로 한다. 장문이나 증빙은 축소 대신 분할 또는 확대 인셋으로 처리한다.
- 확정 프라이머리 컬러와 문구에 맞는 최소 요소만 사용한다. 디자인 밀도는 한 단계만 높이고 선·화살표의 굵기, 간격, 방향과 오브젝트 잘림을 검수한다.

## 금지

- 원본 PPTX 덮어쓰기
- 파일명만 보고 PNG 페이지 번호 추정
- 판단 없이 자동 후보 전체를 재작업 대상으로 확정
- 단순하거나 장식이 적다는 이유만으로 재작업 지정
- 원문·수치·출처·사진·로고·기존 일러스트 임의 변경
- 장문과 증빙을 작은 글씨로 축소해 한 장에 억지로 유지
- 반려 사유를 지우고 이전 버전을 재사용
- 미검수 페이지가 남은 상태에서 최종본 생성
